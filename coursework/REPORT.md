# 课程设计报告草稿与答辩准备（未完成）

题目：《StarryOS 事件通知机制的语义修复、性能优化与系统调用安全加固》。本稿的事件链、评分要求到证据的对应表和五分钟讲稿见 [交付说明](DELIVERY.md)。学生须自行完成个人总结、独立判断和真实贡献。

## 背景与目标

StarryOS 提供 Linux 风格的文件描述符与 eventfd。项目先修复信号量模式返回值，后结合讲义的三类方向补充 `getcpu`、优化非阻塞 eventfd 调用路径，并消除未实现的 seccomp 入口返回成功的问题。这些改动涉及系统调用分发、用户指针检查、原子计数、阻塞唤醒和安全接口错误处理。

## 设计与结果

2026-11-06 补充多生产者任务应用、通知 RTT 测量、独立构建及 2/4 核回归，结果和限制见 [扩展验证](EXTENDED_VALIDATION.md)。普通和信号量两种模式均完成 1024 个编号任务，故障注入场景识别退出码 7。三次独立启动的通知往返统计和原始样本已保留，报告中的历史无竞争写读提速与这次 RTT 测量分别引用。

详见 [原设计](DESIGN.md)、[三方面专题](THREE_ASPECTS.md) 和 [测试报告](TEST_REPORT.md)。同一客体用例在上游原始内核观察到 eventfd 返回 3，而修复后通过；本轮修改前的 `getcpu` 未实现、两个 seccomp 入口虚报成功，修改后测试通过。审查问题处理后的最终内核在单核 QEMU 无竞争 eventfd 写/读对照中下降约 50.35%，只适用于记录的测量条件，不代表整体系统性能。课程整体交付仍需学生完成实际审查、总结、演示及答辩。

后续审查发现随机数可预测、用户调用可触发 panic、凭据接口虚假成功及事件唤醒等缺陷，见 [审查记录](review-20261104/README.md)。这些具体问题已按 [处理记录](SECURITY_FIXES.md) 修复或以明确错误阻断；当前随机数、完整凭据模型和安全隔离仍未实现，报告与演示须明确这一边界。
